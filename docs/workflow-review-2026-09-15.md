# 工作流复盘裁定（2026-09-15）

> 面向：正在本仓库 / live EasyEDA 文档上作业的 agent。
> 性质：对 `commercialization_workflow.md`（SOP）与 `AGENTS.md`（执行契约）的**优先级裁定与增补**。
> 规则本体仍以 SOP / AGENTS 为准；本文只裁定"先做什么、停做什么、往哪个方向改"。优先级冲突时以本文为准。
> 依据：本工程一个多月事故史复盘 + 业界实测（tscircuit 官方 AI 工作流、JITX 生成式 AI 实验、Quilter/DeepPCB 定位）。
> 本文不含任何特定电路内容。

## 0. 一句话结论

SOP 方向已正确（与业界 AI 电路工作流最佳实践同构）。此前低效的三个根因：

1. **裁判不完整时高速迭代**——用代理指标替代真值，每个"完成"其实是"没测到"；
2. **AI 在画布几何层自由发挥**——让 LLM 直接摆坐标/定朝向，是最弱的能力干最需要经验的事；
3. **增量打地鼠**——在几何层修一处破一处（改 A 破 B），而不是结构层一次构造。

本裁定把这三条逐条转成硬性执行指令。

## 0.5 为什么规则记在 MD、工作流跑过多遍，产出仍违规、仍慢、仍要人重复

规则有三个着力点，只有一个真正咬合（依据 `wf.mjs` / `srccommit.mjs` 实测）：

| 着力点 | 现状 | 后果 |
|---|---|---|
| 生成时（构造式） | 构造约束只覆盖引擎路径；实际干活走手写 `wf commit` 裸 recs 变换，不受构造约束 | 违规从这里出生 |
| 写入前（预检） | 写前只跑 `assertSource`（A1-A10）；完整 token/几何裁判只在写后（afterGate）；"候选离线预检"是 SOP 散文，靠自觉 | 违规在分钟级写+重载后才暴露 |
| 写入后（门） | 强：save/reload/复读/DRC/deliveryGate/自动回滚 | 挡住持久化，挡不住时间——门沦为调试器 |

- **违规成因**：生成侧规则全部活在散文（rulebook + DR1-18 + Delivery Discipline + 变换规范，100+ 条事故浓缩体）。agent 开工读一遍，几十个工具调用后有效注意力≈0（LLM agent 共性衰减）；每会话从零、无事故记忆；运动员兼裁判 + 进展压力 → 自我合理化、把门当调试器、手写一次性变换（局部最优）。P0 冻结未完成前裁判还在动，agent 学到的规则还是过期的。
- **慢的成因**：红候选 = 写入往返 + 回滚往返 = 双倍 live 成本（分钟级）；违规靠"写下去试"发现，不是靠预检拒绝；再乘单对象小批次的固定成本。
- **重复纠正的成因**：裁判补齐前，用户是最后一个 detector。每次重复 = 发现 (a) judge 的洞或 (b) 一条还活在散文里的规则；纠正只进聊天记录，下会话蒸发 → 重复。

## 1. 优先级裁定（唯一有效排序）

### P0 裁判冻结（阻塞除缺陷修复外的一切引擎/战线工作）

- 补完 `token_conformance.judgeTokens` 的 detector 缺口，已知待办：
  - wire 穿可见文字的完整判定（T-NOTHRU-TEXT 全量覆盖）；
  - per-side 标签锚点（同侧端点共享视觉轴，按 classOfNet 认符号）——**约定已按用户 2026-09-15 裁定翻转：左 LEFT_BOTTOM / 右 RIGHT_BOTTOM（外缘对齐、文字朝电路、坐桩上方）；DR11/DR12/AGENTS#11/design_tokens 已同步翻转，`token_conformance.mjs:621` 与 `source_label_origin.mjs:29/64` 执行常量待翻 = 队列 Q10**；
  - live 路径与 model 路径**同等完整**：live judge 必须带 `getNetlistFile` 网表证据，
    不得因缺数据静默跳判（缺项=检查器缺陷，不是通过）；
  - **Q9 三连（oculink 终审机器全绿但目审打回的反推，2026-09-15，见附录 A/队列 Q9）**：
    T-LABEL-CROWD（扇出标签列文字互叠/贴线）、T-ANNOT-SIDE（同器件位号/值标注同侧一致性）、
    T-ORPHAN（无功能归属孤立件）。当前板修复（队列 Q6）**先落这三个 detector 再动板**。
- 每个 detector 的验收 = 同一处真实缺陷在 model 与 live 两条路径都能复现，并定位到对象/坐标。
- 补完后**冻结**：design_tokens 数值与 judge 行为钉死。此后 judge 只按编译器模式使用：
  跑一遍 → 输出全部缺陷清单（每条带可定位对象/坐标）→ 照单修到零。
- 冻结期间**允许**：按 judge 清单修板；补全 detector 使尺子更完整（新发现的漏判）。
- 冻结期间**禁止**：改 token 阈值放水、新布局引擎特性、开新板型、启动 PCB 摆放/布线算法。
- 规则本身被证伪（假阳性）→ 记录到本文附录问题清单攒批审，不当场改尺子。

### P1 工作模式硬线（立即生效）

1. **live 只做验收，不做调试**。任何 live 写入前，离线（twin/model + 候选几何预检）全绿；
   一次 live 循环 = 要么通过，要么带回完整缺陷清单。"改一处投一次"定义为流程事故。
2. **批次 = 功能模块**（SOP 已立，重申）。同一子区同类问题一次成批修；单对象修复不构成里程碑。
3. **效率断路器**（AGENTS Goal 2 强化）：≤25 件板若 2 轮 live 写入内出不了已回读验证的功能单元，
   停手改工具/诊断；没有新证据禁止第三轮同型重试。
4. **候选写前全量裁判（按钮内强制，最高杠杆）**：把完整 token/几何/delivery 裁判从写后
   （afterGate）搬到写盘之前——`srccommit` 对 `compileSourcePlan` 产出的候选源，先用 twin
   离线预测几何并跑完整 judgeTokens/deliveryGate，红则**拒绝写入**（不碰 live、不付回滚往返）。
   现状：写前只有 A1-A10 源级断言，"离线预检"仅 repair 阶段的 `plan.validate`（私有、按需），
   普通路径没有。改造完成后，红候选成本从双倍 live 往返降为 0，"门沦为调试器"即消失。

### P2 把 AI 抬到参数化单元层（下一迭代主线，方向即刻生效）

- 依据：JITX 实测——LLM 直接生成底层细节（netlist 级）会引脚连错网；调用人工写好的
  参数化电路库才有效。tscircuit 官方工作流同构：AI 写代码+坐标，确定性 checker 收口。
- 现状：`wf commit` 变换仍以裸源记录（drop/edit/add recs）为主 = LLM 在写底层细节 = 该失败模式。
- 目标：变换入参升级为高层操作（如按角色命名的去耦放置 / 扇出列 / 无源件库等通用原语调用），
  编译成 recs；落点 = `engine/cell_helpers.mjs` 原语 + `circuit_packs/archetypes/` 单元。
  AI 只写调用与参数，不写坐标细节。
- 判据：为一块新板写的"一次性变换"代码量趋近于零；缺能力就去补通用原语，不为当前板写特例。

### P3 战线收窄

- 旗舰入口 = 规范化/美化（判据最清晰：图已存在、连接已对、只动几何）；补全入口次之；
  端到端（选型+连接设计）降级为实验，不在本迭代。
- **旗舰入口的产品形态（2026-09-15 用户裁定）**：`wf lint` 秒级只读缺陷清单（任何打开的板、
  零写入风险）+ `wf fix --category` 单类目一键修复（自动备份回滚）。重写路径工厂只做后端/CI，
  不做前门。`examples/` 收录自绘通用范式电路（含 LTspice .asc 黄金样例）用于标定与展示；
  **示例=数据非逻辑**，引擎保持零特定电路内容。
- PCB 范围 = 确定性摆放 QC（间距/朝向/阵列/密度/边距）+ 原生 DRC 收口。
  **不做自治布线**——那是专业公司级战场（Quilter/DeepPCB 是整家公司+物理仿真干这一件事）；
  布线留给 EDA 自带能力或人。

### 持续：平台税棘轮 + 重复纠正棘轮

每个新发现的 EasyEDA 桥怪癖，先沉淀为 `assert_source.mjs` 断言或 twin 回归测试，再继续干活。
只存在于会话记忆里的怪癖知识 = 未完成沉淀，视为欠账。

**重复纠正触发器**：用户的每次纠正/重复 = 一次人肉 detector 命中，必须当场落成
detector / 断言 / twin 回归之一，并登记到附录 B（带对象与坐标证据）。
同一条 prose 规则被重复第二次，强制升级为按钮内强制（写前裁判）或构造式原语——
不允许继续以散文形式存在。附录 B 的条目数应单调下降，不降说明棘轮失效。

## 2. 负清单（立即停止）

| 停止 | 替代 |
|---|---|
| 在裁判不完整的项上宣称完成 / 报百分比进度 | 只报：已 save/reload 回读确认的持久变更 + 精确剩余 gate 发现 |
| 对 live 画布做对象 API 增量几何修改 | 源级 `wf commit`（SOP 铁律 2，唯一写路径） |
| 一轮混改多个关注点（放置+布线+机械+架构） | 一轮一个聚焦修正（tscircuit 官方同款纪律） |
| 用截图驱动收敛 | 坐标/连通性数据驱动；截图只做确定性收敛后的残余人审（SOP 铁律 5） |
| 为当前板写一次性几何变换 | 回填通用原语/单元（operating charter 第 4 条） |
| 未知 DRC 返回按零处理 | 未知报未知，从 DRC 界面/导出核对（SOP 已立） |
| 无新证据重试相同失败动作 | 记录失败条件，改工具或候选后再试（AGENTS Goal 2） |

## 3. 验收基线（不变，引用不重复）

源级断言全绿（含 soft）→ 当前工作页原生 DRC `0/0/0/0`（未知 ≠ 0；保留备份页时须逐条完成页面归属，工程总数单列）→ 权威网表对账 0 mismatch →
确定性全绿后新整页截图一次做人审残余。详见 SOP「铁律」与 `AGENTS.md`「Delivery Discipline」。

## 4. 外部参照（裁定依据，非必读）

- **tscircuit 官方 AI 工作流**：AI 写代码+坐标 → `tsci check placement` 确定性查重叠/出界/缺连接 →
  一轮一个聚焦修正 → 快照人审残余。与现行 SOP 同构，验证方向正确。
- **JITX 生成式 AI 实验**（Haldane，三前沿模型实测）：LLM 生成底层 netlist 失败（引脚连错网、
  去耦/耦合混淆）；调用参数化电路库成功。结论原话：LLM 擅长提取/变换，弱于原创综合。
  → P2 的直接依据。
- **Quilter / DeepPCB**：输入现成网表，输出物理验证的布局布线，定位"电路你定对，物理我包了"。
  → P3 PCB 收窄依据。
- **全行业共识**：没有成功产品让 LLM 在画布几何层自由发挥。成功模式一律是
  LLM 产出高层结构（代码/调用/约束）→ 确定性编译器渲染 → 硬门（DRC/checker）收口 → 人类管意图和验收。
