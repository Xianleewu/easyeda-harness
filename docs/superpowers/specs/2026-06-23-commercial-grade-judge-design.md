# Spec A —「商用级裁判」:冻结的规则 + EDA 取证验证闭环

- 日期: 2026-06-23
- 状态: 待用户评审
- 适用原则: 本工程是通用、公共工具,**零特定电路内容**(见 `CLAUDE.md` / `AGENTS.md`)。
- 关联: `docs/schematic_design_rulebook.md`、`docs/schematic-design-rules.md`(DR1–DR18)、
  `engine/bridge_*.mjs`(EDA 桥)、easyeda-api-skill(`~/easyeda-api-skill`,真实 EDA 的"手")。

## 1. 背景与动机

本工具的目标:把"器件 + 既定连接意图"排成**商用级原理图**(连接驱动的好摆放 + 朝向 + 直连导线),
投到真实 EasyEDA。过去一个月的失败根因诊断(已与用户对账确认):

- **没有真实裁判**:一直在优化**自己发明的离线门**(geom_qc/label_qc/DR 分),把"测试全绿/门全 0"
  当成功,而真实画布是标签汤——典型的"在模拟器里刷分"。
- **靠想象判好坏**:信离线渲染、几何启发式,而非真实 EDA 的渲染与 DRC。

结论:**先造裁判,再打磨核心引擎。** 计分牌没钉在真实 EDA 上之前,碰摆放/走线就是重蹈覆辙。
本 Spec 只做裁判,不改摆放算法。

## 2. 目标与非目标

**目标(Spec A)**
1. 产出一份**冻结的、通用的、可量的**"商用级原理图" checklist/规则集,每条规则标注**用哪个 EDA
   API 证据判定**。
2. 实现一个**验证闭环 harness**:对已投递到真实 EDA 的板,自动用 EDA API 取证(整图截图、局部
   zoom 截图、DRC),逐条对照 checklist,产出**带真实证据**的体检报告(过/不过 + 失败项 + 证据图)。
3. 用这套裁判,在真实板上拿到**第一个诚实基线**:现在离商用差多少、差在哪(有证据,非想象)。

**非目标(明确不在本 Spec)**
- 不改 ③ 摆放 / ④ 直连走线算法(那是 Spec B)。
- 不做 ① 选件 / ② AI 定连接前端(那是 Spec C)。
- 不追求"通过";本 Spec 只负责**诚实地度量**,允许基线很差。

## 3. 核心原则(不可违背)

1. **标尺事先冻结**:checklist 在度量前定死;**严禁为了让板通过而放宽规则**(堵死"全绿=放宽=gaming")。
2. **唯一证据来自真实 EDA**:判定只用 `sch_Drc.check` + `getCurrentRenderedAreaImage`(整图/局部),
   不用离线渲染、不用几何想象。离线 QC 仅可作"投递前快速预检",**不得**作为通过依据。
3. **零特定电路内容**:规则全部泛化(间距/对齐/分组/密度/正交/标签…);观察到的任何真实电路
   (用户的板、别人的商业图)**只在本地看,只沉淀为通用规则,绝不入库其具体器件/网名/标题**。
4. **快速失败**:桥不可用 / 无活动文档 / 截图取不到 → 明确报错并给出操作指引,**绝不**用离线结果伪装绿灯
   (沿用现有 `accept` local-only fail-closed 约定)。

## 5. 数据流(闭环)

```
冻结 checklist (C3) ───────────────────────────────┐ 既定标尺
                                                    │
已投递的真实 EDA 板                                   │
   │  采证(EDA API,C4)                              │ 逐条核对
   ├─ dmt_EditorControl.zoomToAllPrimitives + getCurrentRenderedAreaImage  → 整图截图
   ├─ dmt_EditorControl.zoomToRegion(模块bbox) + getCurrentRenderedAreaImage → 局部截图(逐块巡查)
   └─ sch_Drc.check(strict,…)                                              → 电气硬判
   │
   ▼  对照 checklist → 证据化报告:每条 规则→过/不过 + 证据(截图/DRC 计数)
   │
   ├─ 全过 → 商用级达标(有证据背书)
   └─ 不过 → 报告指明"哪条、哪块、证据图" → (Spec B 阶段)带证据回炉调摆放/走线
```

判定双证据流,均来自真实 EDA:
- **DRC**(`sch_Drc.check`)→ 电气正确性硬指标(目标 0/0/0/0)。
- **真截图**(整图 + 逐区域局部放大)→ 视觉/商用质量,**靠"真的看"逐条对 checklist**
  (标签不压件、脚真连、模块齐、间距够、走线正交、密度合理)。视觉规则由**具备读图能力的 AI
  代理**读取真实 EDA 截图、对照 checklist 给出判定,每条结论**附对应证据截图**;**用户是规则集
  本身是否合理的最终仲裁者**。能从图元统计转成可量指标的规则尽量转(见 §6.2),以减少纯主观。

## 6. 规则来源:审计 + 商业范例挖掘(本 Spec 的关键)

### 6.1 审计现有规则(C1)
- 逐条检查 `schematic_design_rulebook.md` 与 DR1–18。
- 判据:某条规则若依赖**特定器件/网名/模块标题/某电路特有结构**,即为"demo 偶合 / 非通用",
  必须**删除或重写成与具体电路无关的可量规则**。
- 输出:审计清单(保留/泛化/删除)+ 修订后的通用规则文档。

### 6.2 商业范例挖掘(C2)
- **前置**:bridge 已启动(`cd ~/easyeda-api-skill && npm run server`,49620),用户已在 EasyEDA Pro
  打开目标商业原理图。
- **定位参考图**:`dmt_Schematic.getAllSchematicsInfo` / `getAllSchematicPagesInfo` 枚举 →
  `dmt_EditorControl.activateDocument(tabId)` 激活目标 → 必要时 `getSplitScreenTree`/
  `getTabsBySplitScreenId` 解析分屏与标签。
- **采样观察**(只读):
  - 整图 `zoomToAllPrimitives` + `getCurrentRenderedAreaImage`;
  - 逐区域 `zoomToRegion` + 局部截图,观察标签放置、间距、走线风格、模块分组;
  - 读图元(`sch_PrimitiveComponent.getAll` / `sch_PrimitiveWire.getAll` / `sch_Netlist.getNetlist`)
    统计**可量结构指标**:器件间距分布、栅格吸附率、直连线 vs 网名标签占比、模块密度/留白比、
    引脚朝向一致性、正交率等。
- **提炼**:把上述观察归纳成**通用、可量**的规则(阈值取自真实商业图的统计,而非拍脑袋)。
- **铁律**:提炼过程中**不得记录**参考图的任何具体器件型号、网名、模块标题、项目信息;
  落库的只有"匿名的、通用的"规则与阈值。参考图原始内容只许存在于本地临时分析,**绝不入库**。

## 7. 冻结 checklist 的形态(C3)

规则集为结构化数据,每条形如:

```
{
  id:        'CR-xx',                 // 稳定编号
  dimension: '结构|紧凑|走线|标签|朝向|电气',
  desc:      '通用、与具体电路无关的可量描述',
  evidence:  'drc' | 'image-full' | 'image-region',  // 用哪种 EDA 证据判
  metric:    '如何从证据得出一个可比较的量(或视觉判据)',
  pass:      '通过判据(阈值/0 计数/视觉无违例)',
  severity:  'block | flag'           // block=拦截,flag=提示
}
```

要求:全部通用、可量、可由真实 EDA 证据判定;无任何特定电路字面量。

### 7.1 初始冻结值(2026-06-23 取自商用 RK3576 参考图 10 页 / 371 器件 / 727 线实测)

| id | dimension | 规则 | evidence | pass(初始阈值) | severity |
|---|---|---|---|---|---|
| CR-01 | 电气 | DRC 无 error | drc | error=0 | block |
| CR-02 | 走线 | 可见导线全正交 | geom+image-region | **可见导线 100% 正交**(目视确认无真斜线);原始线段正交率 ≥80%(商用单页下限,见校准记录);真 45° 仅限总线斜入 | block |
| CR-03 | 栅格 | 引脚吸附栅格 | geom | 脚 ≥88% 落 5 单位栅格(商用单页,见校准记录) | block |
| CR-04 | 朝向 | 旋转规范 | geom | 仅 0/90/180/270;0/90 为主;镜像占比 <1% | flag |
| CR-05 | 紧凑 | 器件间距 | geom | 相邻器件中心距集中 ~40–45,min ≥ ~20(不挤不散) | flag |
| CR-06 | 标签 | 专业短桩标签 | geom+image-region | **脚端引一小段水平线、网名文字贴线端、水平对齐、不压器件不重叠**(离顶点中位≈0–10);电源/地用标准 netflag 符号 | block |
| CR-07 | 连接 | 命名网络为主是常态 | geom | 命名网络+标签连接**不扣分**(商用 ~93% 线带网名);块内近距(去耦/输出电容等)优先短直连 | flag |
| CR-08 | 图框 | 标题栏+边框 | image-full | 存在标准标题栏与图框 | flag |
| CR-09 | 标注 | 无源件标注完整 | image-region | 无源件带值/封装/参数(如 `47uF 0805 X5R 25V`);关键网/功能块有文字注释;可选电路有 DNP 标注 | flag |
| CR-10 | 标注摆放 | 标号/阻值构造性摆放 | geom+image-region | 标号+阻值**100% 在器件 body 外**;**垂直脚轴偏移 ~10**(=2×5格,避开穿脚导线且落格);标号与阻值**同侧、沿脚轴错开堆叠**;横放件→上/下侧,竖放件→左/右侧;**绝不压 body/脚/线,绝不互相覆盖** | block |

**重大立场修正(本 spec 据此定调,影响 Spec B):** 实测商用图 **93% 的线用网名标签**连接——
**"标签即罪"是错的**。质量目标不是"消灭标签换直连",而是 **"专业级标签"(命名规范 + 贴线短标 +
对齐不压不散) + 块内近距直连**。CR-02 的正交阈值同样从"100%"修正为"≥94% + 允许少量 45°"。

> 阈值为**初始冻结值**,可经 C2 多页/多参考图统计或 B(目视确认)校准一次并显式记录理由,
> 之后**不得在度量中途为过关而调**(见 §3 反 gaming)。CR-04/05/06 的精确量纲与判据在实现期由 C4 落定。
>
> **校准记录(2026-06-23,允许的一次性校准,有据):** C5 实时基线判 RK3576 商用参考板,原 CR-02=94%/CR-03=95%(取自10页聚合)误将真商用单页判不达标。实测十页正交率 floor≈83%(83.1/83.6/89.7/91.1/91.8/92.3/92.7/93.8/97.5/97.7),且 sub-threshold 段为真斜线(偏移5-10,非浮点噪声)。故 CR-02→80%、CR-03→88%(留余量到真实下限,仍能挡住真散乱布局)。
>
> **B 目视确认(2026-06-23,RK3576 局部放大 2 张,后台窗口 zoom 可读)已敲定:**
> ① CR-06 专业标签 = 脚端短水平桩 + 文字贴线端 + 水平对齐 + 不压器件,电源地用 netflag 符号 ✓;
> ② CR-02 可见导线 100% 正交,~6% 非正交段是符号/引线噪声非真斜线 ✓;
> ③ 命名规范 = 全大写 + 下划线 + 功能名(如 `VCC3V3_WL_VBAT`/`VDD_CPU_BIG_S0`),方向后缀 `_H` ✓;
> ④ 附带发现 → CR-09(无源件值/封装/参数标注、功能注释、DNP 绿框)。
> ⑤ CR-10 标号/阻值摆放哲学(实测 30 无源件):100% 在 body 外、垂直脚轴偏移~10(避导线+落格)、
> 标号与阻值同侧沿轴错开堆叠、横件上下/竖件左右——这是"不压不覆盖"的**构造性**规则,不止"别重叠"。

## 8. 验证 harness 设计(C4)

- **输入**:一个"已投递到 EDA 的板"的引用(当前活动原理图);可选模块区域列表(用于逐块 zoom)。
- **过程**:
  1. 预检桥与活动文档;失败即 fail-closed。
  2. DRC:`sch_Drc.check(strict=true, ui=false, verbose=true)` → 解析 error/warn/info 计数。
  3. 整图证据:`zoomToAllPrimitives` → `getCurrentRenderedAreaImage` → 存本地证据图。
  4. 局部证据:对每个模块/关键区域 `zoomToRegion(bbox)` → 局部截图。
  5. 逐条跑 checklist:每条按其 `evidence` 取对应证据 → 得出过/不过 + 附证据引用。
- **输出**:证据化体检报告(本地,JSON + 证据图):`{ 规则id → {pass, evidence路径, 量/说明} }` +
  汇总(block 数 / flag 数 / 是否商用达标)。报告**不含特定电路内容**(只引用匿名规则 + 证据图路径)。

## 9. 首基线(C5)

用 C4 对**当前引擎产出、已 deliver 的真实板**跑一次,得到首份诚实体检报告。
这是 Spec B(打磨摆放/走线)的**起点度量**:之后每次改动都与此基线对比,用真证据回答"更好/更坏"。

## 10. 错误处理

- 桥不可用 / 端口不通 → 报错 + 打印启动指引(复用 `bridge_check`)。
- 无活动原理图 / 找不到目标参考图 → 报错并请用户在 EDA 中打开/激活,**不臆测**。
- 截图返回空 Blob / DRC 调用失败 → 该条规则标"无证据→不通过(待复采)",**绝不**默认通过。
- 任何环节都不得用离线结果冒充真实证据。

## 11. 测试策略

- **C3 规则集**:每条规则是可单测的谓词/判据;对"含特定电路字面量"做静态扫描断言(零命中)。
- **C4 harness**:用**录制的证据夹具**(脱敏的截图占位 + DRC 计数样例,通用、不含特定电路)单测
  报告生成与判定逻辑;桥交互层用注入式假桥测 fail-closed 路径。
- **C1/C2 产物**:审计清单与挖掘出的规则,做"零特定电路字面量"扫描门。
- 全部接入现有 `npm test`(`node --test`)。

## 12. 复用 vs 新建

- **复用**:`engine/bridge_client.mjs`/`bridge_exec.mjs`/`bridge_run.mjs`(EDA API 访问)、`bridge_check`
  (桥预检)、现有规则文档作为 C1 的审计输入。
- **降级**:`geom_qc.mjs`/`label_qc.mjs`/`layout_audit.mjs` 等离线 QC **降为投递前快速预检**,
  不再作为通过依据(裁判改由 C4 真实证据担当)。
- **新建**:`engine/rubric_mine.mjs`(C2)、`engine/commercial_rubric.mjs`(C3)、
  `engine/commercial_judge.mjs`(C4)+ 对应 `*.test.mjs`。
- **新建·可复用桥工具**:把"**两窗口对比 / 参考图挖掘**"沉淀成可复用模块(`engine/bridge_windows.mjs`:
  枚举窗口 `/eda-windows`、按 `windowId` 定向、激活页、整图/紧窗局部截图、读几何),供 C2/C4 及日后
  "用户板 vs 商业参考图"对比反复调用——不再每次手摸 curl/--window-id。操作配方见记忆 `eda-api-capability-map`。

## 13. 风险与权衡

- **参考图跨窗口可达性**:若商业图在独立 OS 窗口/独立编辑器实例,桥可能只见当前实例;
  缓解:请用户把参考图置于当前编辑器的标签/分屏,用 `getAllSchematicsInfo` 确认可枚举到。
- **视觉判定的可靠性**:视觉规则由读图方对照证据截图判定,主观性通过"每条必附证据图 + 局部放大"
  与 checklist 明确判据来约束;能转成可量指标的尽量转(从图元统计),减少纯主观。
- **抓 gaming**:checklist 冻结在前、阈值取自真实商业图统计;若后续想改阈值,须显式记录理由,
  不得在度量中途为过关而调。
- **截图分辨率上限**:`getCurrentRenderedAreaImage` 整图可能不足以看清细节 → 用 `zoomToRegion`
  逐块局部放大补偿(已纳入 C4 流程)。

## 14. 验收标准(Spec A 完成的定义)

1. 一份**冻结、通用、可量**的商用 checklist(C3),通过"零特定电路字面量"扫描;每条标注 EDA 证据判法。
2. C1 审计完成:现有规则中 demo 偶合/非通用条目已清理或泛化,有审计记录。
3. C2 至少完成一次真实商业图的桥观察,并把提炼出的通用规则并入 C3(参考图内容零入库)。
4. C4 harness 可对真实板产出**证据化体检报告**(DRC 计数 + 整图/局部截图 + 逐条过/不过)。
5. C5 跑出首份诚实基线报告。
6. `npm test` 全绿;新增逻辑有单测;fail-closed 路径有覆盖。
